EpLua

Локальный агент, который по пользовательской задаче и JSON-контексту генерирует LowCode-compatible Lua. Не универсальный coding assistant, а узкий backend-first pipeline с проверкой результата и ограниченным repair loop.

Technical proof

Pipeline виден как система, а не как чат-обёртка

Основной API path `POST /generate` разделён на планирование, prompt additions, генерацию, deterministic validation и semantic validation. Lua выдаёт только generator.

01 request_received API принимает задачу и контекст.
02 planner Собирает компактный TaskSpec.
03 prompter Добавляет короткие подсказки без переписывания контракта.
04 generation Возвращает только JSON object с Lua wrapper.
05 deterministic_validation Формат, синтаксис, static checks и hard rules.
06 semantic_validation Проверка смысла после deterministic pass.
07 response_ready Финальный статус и результат для API/CLI.

Bounded repair

Repair ограничен бюджетом, а не уходит в бесконечный цикл

  1. R1deterministic_validation
  2. R2repair_generation
  3. R3semantic_validation
  4. R4response_ready

Если ошибка repairable, orchestrator делает ограниченный проход generator-а. При исчерпании бюджета CLI может перейти в user-assisted repair вместо скрытых повторов.

Local runtime

Release-контур воспроизводится локально через Docker Compose и Ollama

Конкурсный/demo runtime не опирается на внешние AI API: модель запускается через Ollama, cloud-tags запрещены, а compact параметры фиксируются для предсказуемой проверки.

Contract / constraints

Генерация зажата LowCode-контрактом

EpLua проектировался вокруг строгого output shape: JSON object, Lua wrapper, прямой доступ к LowCode-переменным и запрет лишнего вывода.

Hard rules

  • Ответ только JSON object; Lua внутри строки вида lua{...}lua.
  • LowCode variables доступны через wf.vars, init variables через wf.initVariables.
  • JsonPath, markdown, print, debug output и пояснения вокруг JSON запрещены.
  • error() запрещён: для некорректного входа возвращается nil, false или пустая строка по смыслу задачи.
  • Новые массивы создаются через _utils.array.new(), существующие маркируются через _utils.array.markAsArray(arr).
